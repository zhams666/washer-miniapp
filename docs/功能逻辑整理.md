# 小程序功能逻辑整理

本文档用于对照当前小程序、商家管理端、PC 后台管理页和后端接口的功能逻辑。检查口径以当前代码为准，重点说明用户从入口到业务完成的数据流、页面跳转、接口依赖和异常处理。

## 1. 总体结构

当前项目由四部分组成。

1. 用户端小程序：位于 `pages`、`components`、`custom-tab-bar`、`apis`、`utils`、`config`。主要面向洗车用户，提供首页、门店、门店详情、扫码洗车、充值、订单、钱包、榜单、卡券、教程和我的页面。
2. 小程序内商家管理端：位于 `pages-admin`。主要面向总部、加盟老板、门店店长和门店员工，用于查看门店经营、设备、订单、财务、资产调整、功能说明和个人权限。
3. PC 后台管理页：位于 `admin-web`。主要面向后台管理人员，用于维护门店、设备、用户、订单、钱包、加盟联系信息、结算和看板。
4. 后端服务：位于 `backend`。使用 Spring Boot 提供用户、门店、设备、订单、钱包、次卡、队列、商家管理和 PC 后台接口。

## 2. 用户登录与用户资料

用户身份主要由 `utils/user.ts` 管理，本地缓存包含 `userId`、`openId`、手机号、昵称、头像等信息。页面需要登录时，会先读缓存；如果缓存不足，再调用后端用户接口补齐。

登录相关接口在 `apis/costomer.ts` 和后端 `CostomerController` 中。当前包含微信 code 获取 openId、微信手机号登录、手机号直接登录、历史登录手机号、保存用户信息和上传头像等能力。

当前“我的”页的手机号登录逻辑是直接手机号登录。用户点击手机号登录后，页面展示微信授权手机号入口和历史手机号列表。用户选择微信授权手机号或历史手机号后，前端把手机号提交给后端，后端返回用户信息并写入缓存。这样避免了验证码发送失败导致不能切换用户的问题。

用户资料修改逻辑在“我的”页。昵称、头像等资料先在页面内收集，再调用保存用户资料接口。保存成功后更新本地缓存，并刷新页面显示。

## 3. 首页逻辑

首页入口是 `pages/home/index`，也是 `app.json` 中的 `entryPagePath`。页面显示上方品牌图片、团购核销、扫码洗车、最近门店、快捷功能和底部导航。

上方品牌图片使用 `assets/images/home-dolphin-logo.jpg`。页面使用自适应图片模式展示，保持图片比例，避免拉伸变形。首页文案以“海豚24h自助洗车”为品牌方向。

团购核销按钮跳转到 `pages/voucher-redeem/index`。用户输入第三方团购券号，选择平台和门店后提交核销。该功能用于抖音、美团等外部团购券的自助核销。

扫码洗车按钮调用微信 `wx.scanCode`。扫码结果由 `utils/scan.ts` 的 `parseWashScanResult` 解析。二维码可以包含门店、工位、设备编号等参数。解析成功后，前端通过 `buildStoreDetailScanUrl` 组装门店详情页面链接，带上 `storeId`、`bayId`、`deviceId` 等参数，进入对应门店或工位的洗车流程。解析失败时提示二维码无效。

最近门店逻辑先尝试获取用户定位。定位成功后，请求 `getMiniStoreList`，传入 `userLat`、`userLng` 和已登录用户的 `userId`。后端返回门店距离、工位状态、价格和排队状态。前端按距离选择最近门店。如果小程序门店接口失败，会退回到普通门店列表和工位状态接口组合展示，保证首页不会因为单个接口失败而空白。

最近门店区域原本的开始洗车和立即入场逻辑已经调整为导航。点击后调用 `wx.openLocation`，使用门店经纬度打开微信地图导航。没有门店经纬度时，页面会提示门店定位信息不完整。

首页快捷功能包含门店充值、通用充值、加盟联系、洗车教程。门店充值会带上最近门店的 `storeId` 进入充值页；通用充值进入钱包或充值入口；加盟联系会弹出姓名和手机号填写窗口，提交后写入后端加盟联系表；洗车教程进入 `pages/question/index`。

## 4. 门店列表逻辑

门店列表入口是 `pages/service/index`。底部导航的“门店”会切到该页面。

页面加载时先获取用户定位和用户缓存。然后调用 `getMiniStoreList` 获取小程序门店列表。接口返回的数据会被转换为统一的门店卡片结构，包括门店名称、价格、距离、地址、标签、图片、工位数量、空闲数量、使用中数量、停用数量、排队状态和按钮文案。

如果 `getMiniStoreList` 失败，页面会调用 `getStoreList` 和 `getStoreBayStatus` 作为兜底。兜底逻辑会把普通门店表和工位状态表合并，计算空闲、使用中、停用数量。

门店卡片底部通过圆点显示工位状态。绿色代表空闲，黄色或蓝色代表使用中，红色或灰色代表停用。统计文案展示“空闲、使用中、停用”的数量。

当门店有空闲工位时，按钮显示“开始洗车”。用户点击后进入门店详情，选择具体工位后开始洗车。

当门店没有空闲工位时，按钮显示“排队洗车”或“前方 N 人”。用户点击后进入排队逻辑。排队有效性由后端队列接口和定位校验共同决定。

## 5. 门店详情与工位逻辑

门店详情入口是 `pages/store-detail/index`。它可以从门店列表、首页最近门店、扫码洗车、充值完成返回等路径进入。

页面通过 `getMiniStoreDetail` 读取门店详情。请求参数包含门店 id、用户 id、用户经纬度。返回数据包含门店基础信息、价格规则、标签、工位列表、排队状态、用户钱包余额、次卡权益等。

工位列表会统一映射为前端状态。空闲工位可点击选择；使用中工位展示已洗时长；停用工位不可选择。用户选择空闲工位后，下方按钮变为可开始洗车。

开始洗车前，页面会检查用户是否登录、是否选择工位、钱包余额或次卡是否满足条件。若余额不足，会弹窗提示并带着 `storeId`、`bayId`、`deviceId`、所需金额等参数跳到充值页。充值完成后可返回门店详情继续洗车。

支付方式包括钱包支付和次卡支付。钱包支付使用用户余额扣费，次卡支付消耗用户在该门店或符合规则的次卡权益。实际下单接口在 `apis/order.ts` 和后端 `WashOrderController` 中。

扫码进入时，如果二维码带了工位或设备参数，页面会优先尝试选中对应工位。若该工位不可用，页面会提示当前工位不可开始洗车。

## 6. 排队洗车逻辑

排队接口在 `WashQueueController`，前端主要从门店列表和门店详情触发。核心接口包括加入队列、定位校验和查询队列状态。

当门店没有空闲工位时，用户可以点击排队洗车。前端会获取用户当前位置，并把用户 id、门店 id、用户经纬度提交给后端。后端判断用户是否在门店 100 米范围内。

如果用户在 100 米范围内，后端创建或更新排队记录，并返回队列号、当前位置和前方排队人数。前端显示“前方 N 人”。

如果用户超出 100 米，后端会取消该用户的排队序列号，并把后面的用户向前顺位。前端重新查询队列状态后显示当前结果。

队列状态由后端统一维护，前端只展示状态，不直接计算最终顺序。这样可以避免多个用户同时排队时顺序不一致。

## 7. 洗车中与订单详情逻辑

洗车中页面是 `pages/washing/index`。进入时会读取订单 id、门店 id、工位 id、设备 id 等参数。页面周期性或手动刷新订单状态，展示洗车计时、当前费用、订单状态和结束按钮。

钱包订单按实际时长或后端返回金额展示费用。次卡订单展示次卡状态和剩余时间。次卡订单有固定时间限制，到时后由后端自动停止并完成订单。

用户点击结束订单时，前端调用订单完成接口。完成成功后跳转到订单详情页 `pages/detail/index`。订单详情展示订单号、门店、设备、支付方式、金额、次卡状态、洗车时长和状态日志等信息。

订单列表是 `pages/order/index`。它调用订单接口读取当前用户订单，区分进行中和已完成。进行中的订单按钮显示继续洗车，已完成订单按钮进入详情。

## 8. 充值、钱包与支付结果逻辑

充值入口是 `pages/pay/index`。页面支持从首页门店充值、通用充值、门店详情余额不足、支付结果返回等路径进入。

充值页先读取门店列表。如果 URL 中带有 `storeId`，优先选中该门店；如果没有，则根据用户定位推荐最近门店。页面会提示用户充值赠送余额只限所选门店使用。

充值产品通过 `getRechargeProducts` 获取。用户选择充值档位后，前端调用 `createRechargeOrder` 创建充值订单。若后端返回微信支付参数，前端可调用微信支付；当前测试环境也支持模拟充值结果。

支付结果页是 `pages/pay-result/index`。页面根据充值订单号读取订单状态，并调用 `syncRechargeOrder` 同步结果。成功后展示本金、赠送金额、门店等信息。若充值是从洗车流程进入，成功后可返回对应门店和工位继续洗车。

钱包页是 `pages/wallet/index`。它展示总余额、本金余额、赠送余额、门店余额明细、充值记录和消费记录。钱包明细调用 `getWalletSummary`、`getWalletStoreBalances` 和 `getWalletHistory`。加载失败时统一提示“加载失败”或“余额明细加载失败”。

## 9. 卡券、次卡、积分和榜单逻辑

卡券页是 `pages/discount/index`。它读取用户次卡和会员月卡权益，区分可使用、已用完、过期、锁定等状态。可用卡券可以跳转到对应门店详情使用。

次卡购买页是 `pages/card-purchase/index`。它读取后端卡产品，展示单次卡、月卡、新用户体验卡和 VIP 权益。购买成功后会写入用户卡权益。

积分商城是 `pages/points-mall/index`。当前主要是入口和展示能力，用于后续接入积分商品兑换。

时长榜单是 `pages/ranking/index`，已经放到底部导航位置。页面调用订单时长榜单接口，展示用户排名、洗车时长和次数。

邀请页是 `pages/invitation/index`，用于邀请好友、推广分享等入口展示。

洗车教程是 `pages/question/index` 和 `pages/wash-docs/index`。页面展示洗车步骤和注意事项，帮助用户按流程完成扫码、选工位、充值、开始和结束订单。

## 10. 我的页面逻辑

我的页面入口是 `pages/mine/index`。页面展示头像、昵称、手机号登录入口、会员信息、统计数据、钱包概览和常用服务。

统计数据包括门店数、总余额、洗车次数、卡券数和积分。数据来自门店、钱包、订单和卡券接口。如果用户未登录，则显示默认状态并引导登录。

手机号登录按钮放在头像昵称区域。点击后展示登录弹窗，弹窗上方提供微信授权手机号登录，下方展示 4 个曾用手机号。选择曾用手机号后可直接登录。登录成功后刷新用户信息和统计数据。

常用服务按钮使用白色图标背景，并按功能配置图标。包含洗车订单、我的商户、消费明细、客服中心、我的卡券、积分商城、管理端、修改信息等入口。

管理端入口跳转到 `pages-admin/login/index` 或商家管理首页。普通用户看到的是本地演示角色；绑定了管理权限的账号可以进入对应权限范围。

## 11. 加盟联系逻辑

首页“加盟联系”会打开一个输入弹窗。用户输入姓名和手机号后，前端调用 `submitFranchiseContact`，后端接口为 `FranchiseContactController` 的 `/api/franchise-contacts`。

后端保存姓名、手机号、来源和备注。PC 后台管理页可以通过 `/api/franchise-contacts/admin` 查询提交记录，用于总部跟进加盟线索。

该功能不要求用户必须登录，但需要校验姓名和手机号不能为空。手机号格式由前端做基础校验，后端做最终入库校验。

## 12. 小程序商家管理端逻辑

商家管理端位于 `pages-admin` 子包。登录页是 `pages-admin/login/index`，首页是 `pages-admin/home/index`。

登录接口在 `apis/admin.ts`，核心是 `miniAdminLogin` 和 `miniAdminLocalLogin`。正式登录使用微信 code 换取商家管理身份；本地测试支持平台、加盟老板、门店店长和门店员工模拟身份。

管理端权限由后端 `MiniAdminAuthController` 和 `MiniAdminAuthService` 管理。登录成功后前端缓存 `X-Washer-Admin-Token`，之后所有管理端接口都会带上该 token。

商家管理首页调用 `getMiniAdminCurrent`、`getMiniAdminDashboard`、`getMiniAdminOperationOverview`。页面根据角色展示总部、加盟老板、门店店长或员工可见的数据范围。

管理端左上方已有返回洗车小程序首页的按钮。点击后调用 `wx.switchTab` 回到 `pages/home/index`，用于退出商家管理端。

设备页 `pages-admin/devices/index` 展示当前权限范围内的设备和工位状态，可执行启动、停止等管理操作。

订单页 `pages-admin/orders/index` 展示当前权限范围内的洗车订单，可按门店筛选。

财务页 `pages-admin/finance/index` 展示充值、消费、次卡、核销、营业额等经营指标。

资产页 `pages-admin/assets/index` 支持搜索用户，查看用户钱包和次卡，并可对钱包加款、扣款、罚款或调整次卡次数。

功能页 `pages-admin/features/index` 是功能检查说明页，用于列出小程序当前已实现、部分实现和后续待完善能力。

个人页 `pages-admin/profile/index` 展示当前管理人员资料、角色、门店范围和权限列表。

## 13. PC 后台管理页逻辑

PC 后台管理页位于 `admin-web`，使用 Vite 启动。后台主要面向总部管理人员，不是微信小程序页面。

门店管理用于新增、编辑、启用、停用门店。门店信息包含门店名称、编码、状态、联系人、电话、营业时间、省市区、详细地址、经纬度、备注和前端展示标签。新增门店失败时，应检查后端服务是否启动、门店必填项是否满足、后端日志是否有数据库字段错误。

设备管理用于维护门店工位和设备。前端显示运行中、空闲、停用等状态时，应以后端统一的设备状态字典为准，避免小程序和后台状态不一致。

用户管理用于查询用户资料、余额、次卡和订单。

订单管理用于查询洗车订单、状态、金额、支付方式和状态日志。

财务和支付中心用于查看充值明细、钱包流水、次卡使用、结算明细和结算账单。

加盟联系记录可在后台查询用户从小程序首页提交的姓名和电话，用于后续联系。

## 14. 后端主要接口逻辑

`StoreController` 提供门店列表、门店详情、小程序门店列表、小程序门店详情、工位状态、新增、编辑和删除门店。

`DeviceController` 提供设备列表、详情、新增、编辑、删除、启动和停止设备。

`WashOrderController` 提供订单列表、简单列表、时长榜单、创建订单、开始洗车、完成订单、取消订单、自动停止检查、订单详情、状态日志和支付详情。

`MiniWalletController` 提供充值产品、创建充值订单、查询充值订单、同步充值订单、支付通知、钱包汇总、门店余额和钱包流水。

`MiniCardController` 提供卡产品、我的卡券、卡券汇总、模拟购买和模拟核销。

`WashQueueController` 提供加入排队、定位校验和队列状态查询。该模块负责维护排队顺序、取消超出范围用户、计算前方人数。

`CostomerController` 提供微信 openId、手机号、手机号登录、历史登录用户、用户资料保存和头像上传。

`FranchiseContactController` 提供加盟联系提交和后台查询。

`MiniAdminAuthController`、`MiniAdminPortalController`、`MiniAdminAssetController` 提供小程序内商家管理端的登录、权限、经营看板、设备、订单、资产调整等接口。

`AdminDashboardController`、`AdminOrderController`、`AdminUserController`、`AdminPaymentCenterController`、`AdminWalletRechargeController`、`AdminWalletRefundController`、`AdminWalletFineController`、`AdminStoreController` 提供 PC 后台管理接口。

## 15. 数据权限逻辑

用户端以 `userId` 和 `openId` 识别用户。用户钱包、卡券、订单、排队记录都必须绑定用户。

门店相关数据以 `storeId` 为核心。门店充值赠送余额只在对应门店可用，普通本金余额可按业务规则通用。

工位和设备以 `bayId`、`deviceId`、`deviceCode` 识别。扫码洗车可以直接定位到门店或具体工位。

商家管理端以后台 token 和角色控制权限。总部可查看全部门店；加盟老板可查看旗下门店；门店店长可查看当前门店；员工只查看被授权的功能范围。

## 16. 异常处理逻辑

接口失败时，用户端应尽量保留页面结构，不让页面白屏。首页和门店列表已有接口兜底逻辑。钱包和余额明细有统一失败提示。

定位失败时，页面仍展示门店列表，但距离和最近门店可能无法准确计算。需要用户重新授权定位时，由微信开发者工具或真机授权入口处理。

扫码失败或二维码无法识别时，页面提示二维码无效，不进入洗车流程。

余额不足时，不直接创建洗车订单，而是引导充值，充值成功后带参数返回。

排队超出 100 米时，由后端取消当前排队号并更新队列顺序，前端只展示后端返回结果。

管理端 token 失效时，应返回登录页重新登录。

## 17. 试用版上传前检查项

1. 小程序 `app.json` 必须能被 JSON 正常解析，页面路径和子包路径必须存在。
2. 每个页面至少应有对应的 `.json`、`.wxml`、`.ts`、`.scss` 文件。
3. 底部导航图标、我的页面图标、首页图片等静态资源路径必须存在。
4. TypeScript 文件应能通过基础转译检查，避免语法错误导致白屏。
5. 代码中不能残留真实乱码字符、替换符或私有区字符。
6. 微信开发者工具中需要清缓存并重新编译，尤其是改过 `app.json`、`custom-tab-bar` 或图片资源后。
7. 后端接口地址 `config/url.ts` 必须指向当前可访问的后端服务。
8. 需要使用定位、微信支付、手机号授权、上传头像等能力时，必须检查小程序后台对应权限、域名和隐私声明配置。
