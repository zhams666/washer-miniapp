## PC 管理后台测试方式

PC 管理后台是本机运行的 Vue 页面，不随 `washer-api` 一起部署。为了操作当前 CloudBase 测试数据，启动前将它指向云托管公网地址：

```powershell
cd E:\workspace\自助洗车\washer-main\admin-web
$env:VITE_API_BASE_URL = 'https://<washer-api 公网地址>'
npm run dev:local
```

浏览器打开 `http://127.0.0.1:18073`，进入“门店管理”新建专用测试门店。不要运行 `scripts/start-local.ps1`，该脚本启动的是本地 MySQL 开发环境，不会操作当前 CloudBase 测试数据库。

建议测试数据统一使用明显的前缀，例如：

- 门店编码：`TEST-SH-001`
- 门店名称：`测试洗车门店 001`
- 设备编码：`TEST-WASHER-001`

## 尚未完成或存在限制

- 真实微信支付、退款、支付回调未启用。
- 真实洗车设备控制和设备厂商网关未接入，不应操作真实设备。
- CloudBase 免费 PostgreSQL HTTP API 不支持所有 MyBatis 组合表达式。新功能若使用复杂 `OR`、子查询、行锁或计算表达式，需要改为简单查询加 Java 计算，或改为 PostgreSQL RPC。
- 头像上传目前不适用于 CloudBase 私有测试调用模式；正式上线应使用云存储或已备案的自定义 HTTPS 域名。
- CloudBase 为免费测试环境，需在到期前导出 PostgreSQL 数据和部署配置。
- 微信 AppSecret、CloudBase API Key 等敏感信息只能保存在云托管环境变量；此前出现在截图中的密钥应重置。

## 建议测试顺序

1. 启动 PC 管理后台，创建一间 `TEST-*` 测试门店。
2. 为门店创建测试工位和测试设备，并在小程序“门店”页确认可见。
3. 配置一个测试充值套餐或次卡，验证个人中心余额、卡券和积分展示。
4. 使用模拟设备完成一次“选门店 -> 发起洗车 -> 完成订单”闭环。
5. 在 PC 后台核对订单、钱包流水、设备状态和用户资产是否一致。
6. 每完成一项，在本文对应表格中更新状态，并记录测试门店、用户和订单编号。
